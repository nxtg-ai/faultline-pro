Authentication

Every endpoint except GET /health and GET /status requires an API key in the x-api-key request header.

Request header
x-api-key: flt_prod_your_key_here

Key tiers and permissions

TierPermissionsScan rate limitNotes
freescan, report, upload10 / minuteDefault for new keys
proscan, report, upload, batch100 / minutePass "tier":"pro" on key create
adminall — plus admin-only routes10,000 / minuteThe master FAULTLINE_API_KEY env var is always admin
Getting started locally: Set FAULTLINE_API_KEY=your-secret when starting the server. That value is automatically an admin key. Create additional scoped keys via POST /keys.
Create your first key
curl -X POST http://localhost:3000/keys \ -H "x-api-key: your-admin-key" \ -H "Content-Type: application/json" \ -d '{"name":"ci-pipeline","tier":"pro","permissions":["scan","report"]}'
Response
{ "id": "key_01HX...", "name": "ci-pipeline", "key": "flt_pro_01HX...", // ← save this, shown once "tier": "pro", "permissions": ["scan", "report"], "createdAt": "2026-03-19T21:00:00.000Z" }

Rate Limiting

Scan endpoints (POST /scan, POST /scan/upload, POST /scan/deep, POST /scan/diff, POST /scan/batch) are rate-limited per API key per minute.

HeaderDescription
X-RateLimit-LimitMaximum requests allowed in the current window
X-RateLimit-RemainingRequests remaining in the current window
X-RateLimit-ResetUnix epoch (seconds) when the window resets

When the limit is exceeded the server returns 429 Too Many Requests with {"error":"Rate limit exceeded","code":"RATE_LIMIT_EXCEEDED"}.

Error Codes

All errors return a JSON body with error (human-readable message) and code (machine-readable string).

HTTP StatusCodeCause
200—Success
202—Accepted (async job started)
400VALIDATION_ERRORMissing or invalid request body / params
401UNAUTHORIZEDMissing or invalid x-api-key header
403FORBIDDENKey lacks required permission for this endpoint
404NOT_FOUNDResource does not exist
429RATE_LIMIT_EXCEEDEDPer-minute scan quota exhausted
500INTERNAL_ERRORUnexpected server error
503SERVICE_UNAVAILABLEAll LLM providers circuit-broken
Error response shape
{ "error": "Missing or invalid x-api-key header.", "code": "UNAUTHORIZED" }

Providers

Faultline is FM-agnostic. Pass "provider" in scan request bodies to select a provider. Omitting it triggers auto-detection from environment variables, then falls back through the failover chain.

ProviderEnv VarBest ForNotes
geminiGEMINI_API_KEYLive web grounding (default)Free API key at aistudio.google.com
perplexityPERPLEXITY_API_KEYReal-time search-nativeBest for time-sensitive claims
openaiOPENAI_API_KEYTraining-data verificationGPT-4 class models
claudeANTHROPIC_API_KEYReasoning-heavy documentsHaiku / Sonnet / Opus selectable
mocknoneCI pipelines, offline devReturns deterministic results, no API call
Failover chain: If a provider fails 5 consecutive times its circuit breaker trips for 5 minutes. The server automatically retries the next available provider in the chain: gemini → openai → claude → perplexity → mock. Returns 503 only when all are tripped.

Scan

POST /scan Scan text for claim verification api-key rate-limited ▶

Core endpoint. Submits text to an LLM provider for atomic claim extraction and per-claim verification. Returns a full risk scorecard with EU AI Act compliance mappings. Results are cached by content hash (24h TTL).

Request body
FieldTypeRequiredDescription
textstringrequiredText to analyze. Min 1, max 50,000 characters.
providerenumoptionalgemini | openai | claude | perplexity | mock. Defaults to auto-detect.
Example request
curl -X POST http://localhost:3000/scan \ -H "x-api-key: your-key" \ -H "Content-Type: application/json" \ -d '{"text":"GPT-4 has 1 trillion parameters and 96 attention layers.","provider":"mock"}'
Response (200)
{ "input": "GPT-4 has 1 trillion parameters...", "provider": "mock", "claims": [ { "id": "c1", "text": "GPT-4 has 1 trillion parameters", "type": "fact", "importance": 4 }, { "id": "c2", "text": "GPT-4 has 96 attention layers", "type": "fact", "importance": 3 } ], "verifications": { "c1": { "claimId": "c1", "status": "contradicted", "confidence": 0.87, "explanation": "Parameter count is unconfirmed by OpenAI.", "sources": [] } }, "overallRisk": "high", "complianceReport": { "overallRiskLevel": "high", "riskTier": "limited", "triggeredArticles": [], "mitigations": [] }, "ruleFindings": [] }

Response headers include X-Cache: HIT or X-Cache: MISS and the X-RateLimit-* family.

Scans 1–10 texts concurrently. Uses partial failure semantics — if some texts fail, others still return results. Failed items appear in the errors array with their zero-based index.

{ "total": 2, "succeeded": 2, "failed": 0, "results": [ /* array of ScanResult objects */ ], "errors": [] }
POST /scan/upload Upload PDF or image for OCR scan api-key rate-limited ▶

Accepts a PDF or image file (PNG, JPG, TIFF). Text is extracted via pdf-parse for PDFs and tesseract.js OCR for images, then scanned. Max file size: 10 MB.

Example request (multipart/form-data)

Returns the same ScanResult shape as POST /scan.

Event types

EventFired When
