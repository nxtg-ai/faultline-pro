## #6 js/regex-injection: `packages/api/src/store/rules.ts:88` (before the fix)

**Site.** A rule with `condition: 'regex_match'` carries a caller-supplied `params.pattern`. Before the fix it was compiled at creation only to check syntax (`rules.ts:88`). At evaluation it was compiled again for every claim and executed against the full claim text (`rules.ts:144`). Two routes write rules, `POST /rules` and `PATCH /rules/:id`, and two run them, `POST /rules/:id/test` and `POST /rules/apply` (`packages/api/src/routes/rules.ts`). All of them sit behind `requireApiKey`, so any issued key qualifies, not only admin. `PATCH` merged `params` with no validation (`RuleStore.update`), so a dangerous pattern could be stored without passing through the creation check. Rules are not run by `/scan`: `applyAll` and `evaluateRule` are called only from `routes/rules.ts`.

**Measured** on Node, 10,000-character input, 2026-10-02: `.*x` 29 ms, `.*.*x` 93 s, `a*a*b` 100 s. `(a+)+$` takes 191 ms on 24 characters and doubles with each character added. The input cap alone is not enough, so the checker also refuses polynomial shapes.

**Fix.**
- `packages/api/src/lib/safe-regex.ts` (new). `checkRegexSafety` (line 135) is a small tokenizer that handles escapes, character classes, groups and lookarounds. It refuses: a pattern over 256 characters; a backreference (`\1`..`\9`, `\k<name>`); a repeating quantifier on a group whose body holds a quantifier or `|` (the exponential class, including `(a|a)*`); more than one unbounded quantifier (`*`, `+`, `{n,}`, `{n,m}` with m > 20, the polynomial class); and a path product (bounded repeats times alternation branches) over 256, or over 8 when the pattern also has an unbounded quantifier. The policy is documented in the file header. It over-rejects on purpose. `\w+\s+\w+` and `(?:a|b)*` are refused and can be rewritten as `\w+\s\w{1,20}` and `[ab]*`. `compileSafeRegex` (line 243) combines the check with compiling.
- Creation: `validateRuleInput` refuses with `params.pattern is refused (ReDoS guard): <reason>.` (`rules.ts:104`), and `POST /rules` returns 400.
- PATCH: `RuleStore.update` re-validates the merged params (`rules.ts:298`) and rejects an invalid severity. `PATCH /rules/:id` returns 400 (`routes/rules.ts:136`). A PATCH that does not touch `params` still works on a legacy rule, so a dangerous stored rule can still be disabled.
- Evaluation: `buildMatcher` re-checks the stored pattern once per rule, not once per claim (`rules.ts:189`). A refused pattern is never executed. The rule is returned under a new `skipped` field (`{ ruleId, ruleName, reason }`) in the `/rules/:id/test` and `/rules/apply` responses, and the route logs it at `warn`.
- Text cap: regex conditions see only the first `MAX_MATCH_TEXT_LENGTH = 10,000` characters (`boundedText`, `rules.ts:153`).
- Aggregate budget: up to 500 rules times every claim in a 1 MB body could add up to minutes even if each regex is safe. A shared `RULE_EVALUATION_BUDGET_MS = 1,000` (`rules.ts:131`) stops regex-based rules once it is spent (`rules.ts:232`). Each stopped rule is reported in `skipped`, together with the violations found before the stop.

**Worst allowed shape measured** (10,000 characters, this machine): `.{0,7}.*x` 239 ms, `a?a?a?.*x` 226 ms, `(.*)?x` 94 ms, `.*x` 28–49 ms. Every shape that cost seconds before the path-product limit of 8 is now refused (for example `.*(?:a|a)x8 groups` at 6.4 s, `a?a?a?a?a?a?a?a?.*x` at 10.1 s). One request is therefore bounded by about 1 s of budget plus one execution of roughly 0.25 s.

## #7 js/polynomial-redos: `packages/api/src/store/rules.ts:132` (before the fix)

**Site.** `missing_date_citation` ran `/\d+%|\d+\s*(billion|million|thousand|percent)/i` on the full claim text. On 50,000 digits it took 4.6 s.

**Fix** (`rules.ts:149`). For `.test()` the leading `+` adds nothing, because any match of `\d+X` contains a match of `\dX` at its last digit. The pattern is now `/\d%|\d\s*(billion|million|thousand|percent)/i`, which gives the same answer in linear time. Its input is also capped at 10,000 characters by `boundedText`.

## #8 js/resource-exhaustion: `packages/api/src/store/pdf-report.ts:84` (before the fix)

**Site.** `importanceStars(n)` called `'☆'.repeat(5 - Math.min(5, n))`. `importance` comes from scan data the caller posts to `POST /scan/report/pdf` (inline body) or from a stored scan. For −1e9 the call throws `RangeError`. A large negative value just under V8's string limit (about 2^29) allocates hundreds of MB, and PDFKit then lays that text out. NaN gave `''` silently.

**Fix.** `clampImportance` (`pdf-report.ts:89`) returns an integer 1..5: non-finite input gives 1, fractions are truncated, strings are coerced. `importanceStars` (line 96) always returns exactly five characters. I checked the other `.repeat(` and `Array(n)` uses under `packages/api/src`. The only others are `Array.from({ length: bucketCount })` in `store/status.ts:92`, where `bucketCount` comes from default constants (its one caller, `routes/health.ts:47`, passes none), and two constant `padStart(2)` calls. None take caller data.

## #2 js/unvalidated-dynamic-method-call: `packages/cli/providers/registry.ts:35` (before the fix)

**Site.** `factories[providerName]` on an object literal. `constructor`, `toString`, `__proto__`, `hasOwnProperty` and `valueOf` resolve through the prototype and pass `if (!factory)`. `registerProvider(name, f)`, which plugins reach through `plugins/loader.ts`, could also write `factories['__proto__']`.

**Fix.** `factories` is now a `Map` (`registry.ts:14`), and lookups use `get` and `set` (lines 33 and 46). Unknown names produce the same error message as before: `Unknown provider "<name>". Available: ...`.

## Left open

- **The rule store is global across tenants.** `/rules` is guarded by `requireApiKey`, not admin. Any issued key can create, list, patch or delete rules that every other key's `/rules/apply` then runs. The route comments say "(admin)". Not changed here.
- Rules are held in memory (`RuleStore`), so "stored before this change" covers only rules created on the running machine before deploy. A restart already clears them. The evaluation-time guard is the backstop for that window, and for any future persistence.
- `pdf-report.ts` calls `claim.type.toUpperCase()`, which throws when a posted claim has no `type` and returns a 500. It does not exhaust resources and was not changed.
- The checker is static and conservative. A V8-level fallback (`--enable-experimental-regexp-engine-on-excessive-backtracks`) or running rules in a worker that can be terminated would add defense in depth. Neither was added.
